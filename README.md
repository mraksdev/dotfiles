# dotfiles

Рабочее окружение для разработки на Python и Django: Neovim в роли IDE, zsh с приглашением
Powerlevel10k, tmux и файловый менеджер lf.

Установка — один скрипт. Он проверяет структуру репозитория, сохраняет существующие конфиги
в `~/backup/dotfiles/` и только после этого создаёт симлинки.

## Что внутри

| Каталог | Содержимое |
|---|---|
| `nvim/` | Конфигурация Neovim на Lua, всё под неймспейсом `mraks` |
| `zsh/` | `.zshrc`, `.zshenv`, тема Powerlevel10k |
| `tmux/` | Конфигурация tmux и список плагинов для TPM |
| `lf/` | Конфигурация файлового менеджера lf |
| `setup.sh` | Установщик: проверка, бэкап, симлинки |

## Neovim

### Структура

`lua/mraks/` разделено на две части:

- `core/` — `options.lua`, `keymaps.lua`, `autocmds.lua`: базовые опции редактора, хоткеи, автокоманды
- `plugins/` — по одному файлу на плагин
- `lazy_init.lua` — клонирует `lazy.nvim`, если его ещё нет, и подключает `plugins/` через `import`

Менеджер плагинов — `lazy.nvim`. У большинства плагинов загрузка отложена до события
(`BufWritePre`, `BufReadPre`, `VimEnter`), поэтому конфиг не тормозит открытие редактора.

Базовые настройки в `core/options.lua`: отступы 2 пробела, `expandtab`, номера и относительные
номера строк, подсветка текущей строки, колонка ограничения на 81 символе, постоянный `undofile`
и отключённый `swapfile`.

### LSP и автоустановка серверов

`plugins/lsp.lua` поднимает `mason` вместе с `mason-tool-installer` и поручает ему ставить
и поддерживать в актуальном состоянии эти серверы:

| Сервер | Зачем |
|---|---|
| `pyright` | Python |
| `djls`, `djlsp` | Django |
| `flake8` | линтинг Python |
| `stylua` | форматирование Lua |
| `bashls` | Bash |
| `html`, `cssls` | вёрстка |
| `lua_ls` | сам конфиг на Lua |

Автокоманда `LspAttach` создаёт буферные хоткеи: переименование, code actions, переход
к объявлению. По `CursorHold` подсвечиваются все вхождения символа под курсором, по `CursorMoved`
подсветка снимается. Inlay hints включаются только если сервер их поддерживает — проверка идёт
через `client:supports_method()`, чтобы не получать ошибку на серверах без этой возможности.
На `LspDetach` все хоткеи и автокоманды разбираются.

### Автодополнение и сниппеты

`plugins/blink.lua` — `blink.cmp` как движок автодополнения и `LuaSnip` как движок сниппетов.
Подключены `friendly-snippets` и загрузка сниппетов из формата VS Code, включены signature help
и fuzzy matching, который считается на Lua.

У `LuaSnip` есть build-шаг: нужен `make`, чтобы собрать `jsregexp` — без него не работают
регулярные выражения в сниппетах. `setup.sh` этот шаг не запускает, он происходит при
инициализации плагина.

### Синтаксис, линтинг и форматирование

- `nvim-treesitter` — парсер подставляется по событию `FileType`; если его нет, он доустанавливается
- `nvim-lint` — `flake8` для Python, проверка на `BufEnter`, `BufWritePost` и `InsertLeave`,
  причём только в изменяемых буферах, чтобы не шуметь внутри всплывающих окон LSP
- `conform.nvim` — форматирование по сохранению, порядок для Python: `isort` → `autoflake` → `autopep8`.
  Для Lua — `stylua`, для шаблонов Django — `djlint`, для HTML — `prettier`.
  Форматирование по умолчанию отключено для C и C++

## zsh

Плагины ставятся через `zinit`: подсветка синтаксиса, автодополнение, `autosuggestions` и `fzf-tab`.
Приглашение — Powerlevel10k в конфигурации `lean`: nerd-font, 2 строки, transient prompt,
instant prompt, чтобы не терять время на инициализацию.

Отдельно подключён `pyenv` — им управляются версии Python в проектах. Есть алиасы для `nvim`,
`lsd` и активации виртуального окружения, поиск по истории на `Ctrl+P` и `Ctrl+N`.

## tmux

Префикс — `C-Space`, индексация окон и панелей с 1, режим `vi` в copy-mode, мышь включена.
Разбиение и создание окон наследуют текущую директорию, так что проект открывается один раз.

Плагины управляются через [TPM](https://github.com/tmux-plugins/tpm): `tmux-sensible`,
`vim-tmux-navigator`, `tmux-yank` и `catppuccin` для темы в варианте `frappe`.

## lf

Файлы открываются в Neovim прямо из менеджера, если определяются как текстовые. Есть переходы
`gh` в домашний каталог, `gr` в корень и `gd` в каталог с dotfiles. Поиск по `Ctrl+F` идёт
через `fzf` в глубину до трёх уровней.

## Установка

Предусловия, которые нужно поставить отдельно: `neovim`, `zsh`, `tmux`, `lf`, `git`, `make`,
`pyenv` и `node`. `zinit`, `lazy.nvim` и `powerlevel10k` подтягиваются автоматически при первом
запуске. Языковые серверы, линтеры и форматтеры ставит `mason` при первом запуске Neovim.

```sh
git clone git@github.com:mraksdev/dotfiles.git ~/dotfiles
cd ~/dotfiles
./setup.sh
source ~/.zshrc
```

Скрипт написан на POSIX `sh`. Сначала проверяет наличие всех каталогов, затем переносит
существующие конфиги в `~/backup/dotfiles/<имя>_<метка>` и только после этого создаёт симлинки,
так что исходники остаются в бэкапе, даже если что-то пойдёт не так.
